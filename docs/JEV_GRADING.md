# Jev 复习打分

在笔记预览的小节标题旁设置得分点，复习时只写自己的答案，提交后再显示标准和成绩。

## Jev 的三种使用方式

按 TypeSafe 官方文档核对（2026-09-21）：Jev 接收共享的 `state` 和一组有类型的 `questions`，直接返回结构化结果，不生成解释文字。

| 类型 | 用途 | 在复习产品中的适用场景 |
| --- | --- | --- |
| Noul | 判断一个命题是否成立，返回“是”的概率 | 判断是否提及某个必要条件 |
| Choice | 从预设选项中选择一项，返回概率分布和置信度 | 将答案归为预定义的错误类型 |
| Score | 按有序的文字标准评分，返回期望分数、概率分布和置信度 | 按每个关键得分点评估回忆完整性 |

本次使用 Score：每个得分点独立提问，一次请求批量评估。每点等级为 0（未覆盖或核心错误）、1（部分正确但不完整）、2（完整正确，允许同义改写）。总分为各点原始分数的等权平均值除以 2，再乘以 100；不是把“正确概率”直接当作掌握程度。

官方来源：[模型介绍](https://docs.typesafe.ai/introduction)、[Noul](https://docs.typesafe.ai/primitives/noul)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Score](https://docs.typesafe.ai/primitives/score)、[HTTP API](https://docs.typesafe.ai/api)。

## 使用流程

1. 将笔记保存并「纳入复习」，切换到 Markdown 预览。对应小节标题旁会出现「＋」；点击可新增得分点，可设置多个，每点最多 500 字，每小节最多 30 点。
2. 得分点以小标签显示在标题旁；超过 5 个可见字符显示前 5 个字加「…」，鼠标悬浮或键盘聚焦可查看全文。点击标签可修改或删除。截断只影响标签显示，存储和 Jev 请求使用完整内容。
3. 在「设置 → Jev 智能打分」打开开关，填入并保存 TypeSafe 官方 API Key。需已开通 Jev 访问权限，暂不支持 OpenRouter 等网关的 Key。
4. 在「今日待复习」输入答案，点击「提交答案并评分」。答案在揭示前固定，失败重试使用同一份答案。
5. 查看逐点分数、覆盖等级、置信度及百分制总分，结合回忆费力程度选择 Again / Hard / Good / Easy。

得分点不会放进复习队列，也不会在作答前拉取到复习页面。学习页和复习页都不再提供得分点编辑表单；旧题同样在笔记预览中补充。查看上下文或空答案揭示只进入人工核对，不调用模型。Jev 不决定复习间隔，也不会自动提交 FSRS 评级。

## 存储与接口

- schema v2 新增 `ReviewRubric` 表，以稳定的 block ID 保存得分点，随知识库数据库备份。升级沿用现有迁移前备份机制；原有题目目标与学习进度保留。
- 开关保存在设备的应用配置目录。API Key 存 Windows 凭据管理器 `RecallMD/Jev/TypeSafe`；界面只能读到是否已保存，不回显密钥。关闭开关保留 Key，删除 Key 同时关闭打分。
- Rust 调用 `POST https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`。仅发送本题题目、关键得分点和提交的答案，不上传笔记全文或知识库。
- 请求有 10 秒连接超时、30 秒总超时、1 MiB 响应上限；禁止自动重定向，不自动重试计费请求。错误信息不透传上游响应正文或 Key。
- 预览读取标准时核对文档版本；保存时再核对磁盘、索引版本以及原有得分点，防止外部编辑或并发修改导致错配、覆盖。保存不要求题目到期，不消耗日配额，并使旧复习令牌失效。
- Jev 请求前后均校验复习令牌。题面、标准、参与状态或复习状态变化后拒绝旧结果。切题或离开页面会忽略迟到的结果。
- 置信度低于 0.6 的得分点显示「待核对」，并暂停展示该题的百分制总分。这是产品提示阈值，不代表已验证的模型准确率；其余可判断的得分点继续展示，用户结合原文手动选择复习评级。

## 验证边界

自动测试覆盖请求格式、标准与答案隔离、分数归一化、缺失/异常返回、HTTP 鉴权/限流/服务异常、禁用时不请求网络、迁移保留旧数据、得分点保存和过期会话拒绝。浏览器开发预览使用固定模拟分数，并明确标注「未调用 Jev」，不会发送真实请求。

2026-09-21 已通过用户授权的真实 API 验证，返回模型为 `jev-1.13.0`。接口接受当前自定义 `state` 和对象形式的 `instructions`，所有成功响应均通过生产解析器。小样本中发现部分中文口语和关键词堆砌评分不稳定，因此增加上述低置信度保护；不能将接口验证视为题库准确率验证。详见 [真实调用验证记录](JEV_LIVE_VALIDATION.md)。

`src-tauri/src/jev.rs` 内的三项 `live_*` 测试默认忽略。仅显式运行时才读取进程环境 `RECALLMD_JEV_TEST_KEY` 并调用官方 API；可用 `RECALLMD_JEV_REPORT_PATH` 输出不含密钥的报告。普通单元测试不调用真实 API。
