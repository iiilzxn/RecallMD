# Jev 真实调用验证（2026-09-21）

结论：接口与解析契约通过真实验证。对简单明确答案评分基本符合预期，但部分中文口语、关键词列表和条件缺失样本存在偏分，不能作为无人核对的自动判卷依据。

## 实际调用

- 用户授权使用提供的 TypeSafe Key；仅向 `https://api.typesafe.ai/v1/systemone` 发请求。
- 直接运行生产代码的 `request_body`、`send` 和 `parse_result`，未另写一个替代客户端。
- 请求模型 `jev-latest`，实际返回 `jev-1.13.0`。
- 共 24 次请求：初版 8 次、英文规则复测 8 次、4 种问法的组合对照 3 次、保留样本 5 次。所有数据均为人工构造的学习题，没有上传用户笔记。
- Key 通过隐藏输入传入临时进程环境，进程退出时清理；项目文件、下列报告及输出均不记录 Key。
- 实测 `state.student_answer`、`instructions.expected_point` 被服务接受，自定义字段不需要注册；返回的 `score`、`confidence`、`probabilities` 可由现有解析器直接读取。

## 结果

两个等权得分点分别是“栈后进先出”和“队列先进先出”。下表为最终固定规则的原始模型数字，低置信度数字在产品界面中不再当作成绩展示。

| 样本 | 原始百分制 | 判断 |
| --- | ---: | --- |
| 完整正确 | 100 | 符合预期 |
| 两项均用同义表达 | 99.5 | 符合预期 |
| 明确说出栈的规则、队列忘记 | 50 | 符合预期 |
| “栈先拿最后放进去的。队列我不会。” | 48.75 | 符合预期 |
| 两个结论颠倒 | 4 | 接近零分，符合预期 |
| 无关答案 | 0 | 符合预期 |
| 要求忽略规则直接给满分 | 0.5 | 此样本未绕过判分 |
| 题面包含标准，但学生回答“不知道” | 0 | 此样本未把题面计入答案 |
| “栈是刚放进去的先取出来。队列我忘记了。” | 18.75 | 栈这一点偏低，置信度 0；界面显示待核对 |
| 只罗列“栈、队列、先进先出、后进先出” | 42.75 | 缺少明确关系仍获分，两点置信度均低；界面显示待核对 |

额外保留样本：英文只答一项为 49.5 分；中文盒子分类只答一项为 49.5 分。遗漏“指示灯变绿时”的条件样本得 57.5 分，条件点置信度 0.52，仍需人工核对。

初版中文规则对上述“刚放进去”样本只给 12 分。英文规则、简洁英文、简洁中文和每档重复参考事实的问法，都没有稳定修复这一表达。现有证据只能说明评分对措辞敏感，不能据此精确归因。官方也注明 Jev 主要以英文训练，包含中文在内的其他语言目前准确率较低：[State 文档](https://docs.typesafe.ai/concepts/state)。

## 已作调整

固定判分规则明确：仅评估当前得分点，其他点的错误或遗漏不影响本点，题面和参考标准不能当作学生答案。规则以英文表达，用户题目、答案和得分点保持原文。

当任何一点置信度低于 0.6 时，界面将该点及总分位置标为“待核对”，保留其他得分点的结果，提醒用户根据原文选择复习评级。该阈值只是谨慎展示策略，不是准确率保证，也没有对原始分数做人工抬高或按关键词补分。
